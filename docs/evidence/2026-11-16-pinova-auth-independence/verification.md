# شواهد اصلاح ورود و استقلال مسیر خرید

کاندید توسعه: `1.1.0`، بر پایهٔ
`be084b8aa2c9ca5953ab39c13d2361bb32363497`، شاخهٔ
`work/pinova-auth-independent-accounts`.
نسخهٔ نصب‌شده روی سایت همچنان `1.0.1` است. ساخت بسته به معنی انتشار یا نصب نیست.

## دامنه

- ورود بومی پینوا برای موبایل، ایمیل و نام کاربری، همراه با حفظ ثبت‌نام ایمیلی Core.
- تکمیل ایمیل حساب موبایلی با کد تأیید، برای همان شناسهٔ کاربر و بدون ادغام حساب.
- واگذاری مسیرهای حساب، شارژ و گردش کیف پول به صاحبان بومی آن‌ها.
- جایگزینی بی‌صدای پلن قبلی با انتخاب جدید، بدون نمایش سبد خرید؛ حفظ سفارش‌ها و شواهد پرداخت.
- استفاده از API پذیرش رسید Bridge به‌جای تکرار سیاست آن در Core.

هیچ وابستگی اجباری میان Core، Bridge و TeraWallet اضافه نشده است. وابستگی‌های
پیشین آن‌ها به ووکامرس و وابستگی Core به Elementor و Pinova موضوع این تغییر نیستند.

## شواهد محلی

پیش از اصلاح، آزمون‌های هدفمند خطاهای تصاحب مسیر حساب و سبد عادی و سپس چهار
خطای حفظ نشست ورود/ذخیرهٔ پیام را نشان دادند. پس از اصلاح، این بررسی‌ها موفق شدند:

- `python3 tools/check.py` و `python3 tests/governance.py`
- `php tests/bootstrap.php`
- `php tests/checkout-context.php`، شامل fixtureهای احراز هویت و انتخاب محصول
- `php tests/independence.php`
- `php tests/migration.php` با پوشهٔ موقت خصوصی بیرون از گیت
- `python3 tests/release.py` و `python3 tests/package.py`
- `python3 tools/package.py`
- بررسی نحو ۳۱ فایل PHP و `git diff --check`

fixtureها داده، کاربر، نشست و مرز سفارش مصنوعی دارند. این نتایج اثبات اجرای واقعی
MySQL، مهاجرت نشست پینوا، ارسال پیامک یا ایمیل و پرداخت روی وردپرس نیستند.
آخرین نتیجه شامل ۳۳ بررسی احراز هویت، ۴۲ بررسی انتخاب/نشست و ۸۰ بررسی استقلال
بدون شکست است. مسیر مثبت بازبینی مبلغ، مسیرهای stale و busy و اجرای shutdown
مصنوعی، انتخاب تازه را حفظ می‌کنند. callback واقعی ارسال/تأیید کد تکمیل ایمیل نیز
اجرا شد؛ تکمیل ایمیل login نمی‌کند و ورود عادی همچنان login می‌کند.

## بازبینی مستقل

بازبینی `20261116-090134-6bc532ca` با هشت منظر فنی، پنج یافته را تأیید کرد.
هر پنج مورد اصلاح و در بازبینی تکمیلیِ مستقل بسته شدند:

1. قفل و تازه‌خوانی برای درخواست قدیمیِ بازبینی مبلغ ووکامرس.
2. جلوگیری از ذخیرهٔ snapshot قدیمی در checkoutی که قفل را نگرفته است.
3. مهار دکمهٔ تغییر روش ورود هنگام درخواست OTP.
4. هدایت GET تسویهٔ قدیمی به انتخاب جاری، همراه با حفظ انتخاب صریح تازه.
5. آزمون callback واقعی تکمیل ایمیل و کنترل اثر login.

نتیجهٔ تکمیلی در ساعت `2026-11-16T09:39:20Z`، «آماده برای پیش‌نویس درخواست ادغام»
بود؛ یافته یا مانع باز برای همین دامنه باقی نماند. بازبینی و آزمون واقعی وردپرس
دو واقعیت جدا هستند و نتیجهٔ اول جایگزین دومی نیست.

## تغییر مجاز تنظیمات سایت

اعلان‌های `wpvpn_subscription_ready` و `wpvpn_issuance_review` با API تنظیمات
رسمی ووکامرس فعال و وضعیت آن‌ها دوباره خوانده شد. نسل معتبر هر اعلان توسط hook
خود Bridge ساخته شد. مقایسهٔ هش فایل‌های PHP، JS و CSS در سه افزونهٔ نصب‌شده
هیچ تغییری نشان نداد. ایمیل آزمایشی ارسال نشد و سقف عمومی حافظهٔ PHP تغییر نکرد.

## پذیرش باقی‌مانده

مرورگر واقعی، اجرای جاوااسکریپت، پیامک، ایمیل و خرید واقعی آزمایش نشده‌اند.
محیط محلی runtime جاوااسکریپت ندارد. آزمون کامل سایت طبق دستور مالک پس از
هماهنگی گزارش‌های افزونه‌های دیگر انجام می‌شود. پیش از نصب باید این سناریوها ثبت شوند:

- انتخاب A، بازگشت و انتخاب B؛ نمایش فقط B و تعداد تازه، بدون اخطار سبد.
- ورود موبایلی، ورود ایمیلی و ورود با نام کاربری، با حفظ انتخاب.
- تکمیل ایمیل همان حساب و رد ایمیل متعلق به حساب دیگر و کد تکراری.
- شارژ و گردش بومی Wallet و checkout محصول عادی.
- پرداخت بانکی و رسید خصوصی، مجوز مالی و تحویل و اعلان از مسیر Bridge.
- نبود هریک از سه افزونه و فعال‌ماندن قابلیت‌های مستقل دو افزونهٔ دیگر.

انتشار، نصب و نتیجهٔ آزمون سایت باید جدا از موفقیت آزمون‌های محلی گزارش شوند.
